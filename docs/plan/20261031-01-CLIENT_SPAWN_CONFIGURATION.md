# 控制器客户端启动定制及依赖匹配

## 任务目标

- 为控制器 Rust 客户端提供兼容的进程启动定制接口，使桌面宿主在自动启动控制器时统一隐藏命令窗口。
- 保留现有配置结构体、构造函数、控制器协议和 C 接口；定制选项按客户端隔离，克隆客户端共享相同设置。
- 先验证并发布所需 Rust 客户端 SDK，再匹配 LuaSkills 依赖及自动启动路径。
- 用户要求暂不打标签；本阶段不创建任何 Git 标签，不发布 LuaSkills。

## 基线与工作区

- 使用最新远端主分支的独立工作区，保留原主工作区和其他工作区中的未提交修改。
- 控制器仓库当前版本为 0.2.4；注册表客户端最新版本仍为 0.2.3。客户端新增启动接口采用 0.2.5，控制器二进制及协议不变。

## 执行步骤

1. 沿源码确认自动启动及重连路径、现有客户端构造和配置归属。
2. 新增构造接口，接收线程安全的启动配置回调；在每次实际启动前、标准参数和 IO 配置完成后调用。
3. 保留旧构造函数默认行为，不向现有公开配置结构体添加字段。
4. 验证真实自动启动、客户端克隆共享、调用次数、旧配置兼容和 Windows 无窗口行为。
5. 完成格式、静态检查、SDK 测试及包验证，记录发布内容后发布客户端 crate。
6. LuaSkills 使用已发布 SDK 绑定引擎模式，验证控制器桥接及原有窗口覆盖，更新文档。

## 技术选型

- 使用标准库 `Command` 定制回调和现有客户端共享状态，不引入依赖。
- 使用新增构造函数避免改变旧构造签名及公开配置字面量。
- LuaSkills 复用自身统一窗口策略，避免 SDK 和宿主各自维护互相矛盾的模式。

## 验收标准

- [ ] 旧构造函数和公开配置不变，新接口只影响选择它的客户端。
- [ ] 正常自动启动及后续自动启动均调用同一配置回调。
- [ ] Windows 真实子进程验证无控制台窗口，测试不访问真实数据库服务。
- [ ] SDK 格式、测试、静态检查及发布包验证通过。
- [ ] 客户端 crate 已发布且注册表可获取，再完成 LuaSkills 依赖匹配。
- [ ] 无标签、无 LuaSkills 发布，未覆盖其他工作区修改。
