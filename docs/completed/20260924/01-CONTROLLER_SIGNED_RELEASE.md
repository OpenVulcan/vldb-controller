# 控制器锁修复与签名发行

## 目标

修复控制器内嵌的 SQLite 文件锁缺陷，接入与 VMM、VMMM 相同的 Certum 和 OpenPGP 签名，发布兼容的 `v0.2.4`，再更新 VMM 完整发行包依赖。

## 步骤

1. 从远端主分支创建隔离工作区，保留用户原工作目录中尚未提交的开发内容。
2. 将 SQLite 依赖固定到已修复版本的完整 Git 提交，只更新控制器工作区版本与该依赖锁定记录。
3. 增加真实内嵌 SQLite 所有权回归，验证竞争拒绝及释放后重新获取。
4. 接入已实测的固定安装包、动态口令、Windows 签名与 Linux 分离签名工具，完成源码及脚本审查。
5. 在五个平台构建并测试，草稿汇总二十四项资产。
6. 下载后验证所有摘要、Windows 固定证书与时间戳以及四份 Linux 签名；连续五轮复审通过后公开版本。
7. 更新 VMM 的固定控制器版本和摘要，继续正式发行流程验证。

## 技术与验收

沿用现有 Rust 工具链、数据库协议和 ABI。SQLite 使用固定 Git 提交，不依赖未发生的 crates.io 发布。签名仅使用组织机密，公开身份保存在仓库。macOS 保持不签名。不得在跨平台测试或下载校验未完成时公开不完整版本，不得覆盖既有公开标签。

## 当前状态

SQLite 依赖及工作区版本已更新；锁定文件仅改变三个工作区包的版本及 SQLite 来源。原工作目录未修改。真实回归首次本机构建因环境未设置 `protoc` 失败，已使用锁定依赖携带的明确编译器路径重试并通过。动态口令标准向量、七段 Bash 脚本语法、工作流静态检查与差异检查通过；本机 OpenPGP 专项明确跳过，须由 Linux 原生任务运行。五平台构建、实际签名及下载验证待执行。
